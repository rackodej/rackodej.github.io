postMessage targetOrigin bypass via IP normalization

Регулярка https?://[^.]+[.]target[.]com пропускает http://2130706433/.target.com: [^.]+ означает один или больше любых символов, кроме ., поэтому съедает 2130706433/ — в том числе /.

В итоге postMessage отправляет данные на http://127.0.0.1, а не на поддомен target.com.

#security/web/regex

Discourse SNS webhook RCE

Неявный вызов open(value) — это Kernel.open(value): путь открывает файл, а строка с ведущим | — процесс с каналом ввода-вывода

Вызов URI.open(value) также обманчив: URI::HTTP(S)#open всё, что не распознано как URI, передаётся обратно в Kernel.open.

Пример:

require "open-uri"
URI.open("|id") { |io| io.read }
